# Полис — каталог страхования Казахстана

Сервис-витрина, который помогает разобраться в видах страхования в Казахстане и перейти
к оформлению у страховой компании. Пользователь выбирает, для кого нужна страховка
(«Для себя» или «Для бизнеса»), находит подходящую категорию, сравнивает проверенные
предложения страховщиков и уходит на официальный сайт компании для расчёта и покупки.

Проект не продаёт страховку: он объясняет условия, показывает подтверждённые продукты
и даёт прямую ссылку на страницу оформления у страховщика.

Текущая версия — **1.1.0**. История изменений: [`CHANGELOG.md`](./CHANGELOG.md).

---

## Что внутри

- Две аудитории с раздельными каталогами: физлица и юрлица/ИП. Переключатель виден
  с первого экрана, выбор запоминается и не смешивает предложения разных аудиторий.
- 15 категорий: 7 для физлиц (ОГПО ВТС, КАСКО, ДГПО, квартира, здоровье, поездки,
  жизнь) и 8 для бизнеса (работники, автопарк, имущество, грузы, СМР,
  ответственность, экология, отраслевые программы).
- 62 проверенных предложения от 6 страховщиков: Nomad Insurance, Евразия, Amanat,
  Centras Insurance, Freedom Finance Insurance, Halyk Life.
- Обязательность продукта задаётся **на уровне предложения**, а не категории: в одной
  категории спокойно живут обязательный и добровольный продукты, и каждый показывает
  свой статус с пояснением и условием применения.
- Поиск по категориям и компаниям, фильтры по компании, способу оформления и
  обязательности — работают совместно, счётчик считает фактические результаты,
  сброс возвращает исходный список, пустое состояние честно объясняет причину.
- Отдельные страницы для категорий, предложений и компаний, страница «О сервисе»,
  страница поиска, страница 404 и внутренняя демо-страница `/ui-kit/`.
- Общая дизайн-система: токены, 22 компонента, иконки Lucide, официальные логотипы
  страховщиков, сдержанные анимации, менеджер уведомлений.
- SEO: canonical, Open Graph, JSON-LD, `sitemap.xml`, `robots.txt`, `/version.json`.
- Доступность: пропуск к содержимому, полная работа с клавиатуры (включая подсказки
  поиска и мобильное меню), `aria-current`, `aria-live`, корректная структура
  заголовков, поддержка `prefers-reduced-motion`.

## Технологический стек

| Что | Чем | Почему |
| --- | --- | --- |
| Фреймворк | [Astro 7](https://astro.build), `output: 'static'` | Страницы собираются в статический HTML: быстрая загрузка, минимум клиентского JS, простой хостинг |
| Язык | TypeScript, `astro/tsconfigs/strict` | Типизированный слой данных: опечатка в поле продукта ловится на сборке |
| Стили | CSS-слои + дизайн-токены | Без CSS-фреймворка, предсказуемый результат, смена палитры в одном файле |
| Иконки | [`@lucide/astro`](https://lucide.dev/guide/astro) | Иконки вставляются как инлайн-SVG на сборке, в клиент не уходит ничего лишнего |
| Анимации | [`motion`](https://motion.dev) (`motion/mini`) + CSS-переходы | 4 КБ на контролируемое появление и уведомления; простое — на CSS |
| Шрифт | `@fontsource-variable/manrope`, самохостинг | Кириллица, вариативные начертания, без запросов к сторонним CDN |
| Интерактив | Небольшие модули в `src/lib/` | Поиск, фильтры, меню, уведомления и проверка обновлений без клиентского фреймворка |
| Проверки | `scripts/verify-links.mjs`, `scripts/regression-tests.mjs` | Ссылки и регрессии проверяются отдельными скриптами в CI |

Клиентского фреймворка (React/Vue) нет намеренно: фильтры, поиск, меню, уведомления
и проверка обновлений укладываются в несколько модулей и не требуют гидратации.

## Установка и запуск

Требуется **Node.js 22.23.4 или новее** (нижняя граница задана Astro 7).

```bash
npm ci            # установка зависимостей по lock-файлу
npm run dev       # dev-сервер на http://localhost:4321
npm run build     # сборка статики в dist/
npm run preview   # локальный просмотр собранной версии
```

## Сборка и проверки

```bash
npm run check            # типы и разметка Astro — должно быть 0 ошибок
npm run build            # сборка: 91 страница в dist/
node scripts/regression-tests.mjs   # 27 регрессионных проверок по dist/
npm run verify:internal  # внутренние ссылки в собранных страницах (нужен build)
npm run verify:links     # внешние ссылки на сайты страховщиков
npm run version:info     # содержимое dist/version.json
```

`verify:links` опрашивает 69 уникальных внешних адресов из `src/data/products.*.ts`
и разделяет два разных случая:

- **подтверждённо битая ссылка** — сервер ответил 404/410. Это надо чинить;
- **проверка недоступна** — таймаут, DNS, 403/429/503 (защита от ботов). Такую ссылку
  нужно открыть вручную в браузере, но это не ошибка проекта.

Код возврата `1` бывает только при подтверждённых 404/410. Флаг `--soft`
(`npm run verify:links:soft`) делает шаг незаваливающим — именно так он запускается в CI,
чтобы временная недоступность чужого сайта не ломала сборку.

`verify:internal` читает `dist/` и проверяет, что каждый внутренний `href` ведёт на
существующую страницу.

### Проверка в реальном браузере

Статические тесты не видят, что карточка осталась на экране из-за CSS. Поэтому
поведение проверяется в настоящем браузере (headless Chrome через `puppeteer-core`):
25 сценариев на ширинах 390, 768 и 1280–1440 px — видимость карточек после фильтрации,
сохранение аудитории, полное мобильное меню, клавиатура в подсказках, читаемость шагов
оформления на телефоне, загрузка всех логотипов, очередь и таймеры уведомлений,
`prefers-reduced-motion`, отсутствие горизонтальной прокрутки.

Порядок ручной проверки:

```bash
npm run build
npx serve dist -l 4321        # или python3 -m http.server 4321 -d dist
```

Затем откройте `http://localhost:4321` и пройдите чек-лист:

1. Введите в поиск несуществующий запрос — на экране ноль карточек, а не только «Найдено 0».
2. Выберите компанию в фильтрах — остаются только её предложения.
3. Скомбинируйте компанию, способ оформления и обязательность, затем нажмите сброс.
4. Откройте ДМС и КАСКО — статус «Добровольно», у ОГПО — «Обязательно».
5. Переключите аудиторию, уйдите в бизнес-раздел и вернитесь на главную — выбор сохранён.
6. Откройте мобильное меню на 390 px — видны разделы, «Компании» и «О сервисе», Escape закрывает.
7. В подсказках поиска пройдите стрелками вниз и вверх, выберите Enter, закройте Escape.
8. Откройте страницу предложения на 390 px — шаги идут вертикально, текст не обрезан.
9. Убедитесь, что везде настоящие логотипы, а не буквенные заглушки.
10. Нажмите кнопки демонстрации уведомлений на `/ui-kit/` — проверьте появление, закрытие, таймеры, очередь.
11. Включите в системе «уменьшить движение» — анимации исчезают, контент остаётся доступным.
12. Проверьте на 390, 768 и 1440 px: нет горизонтальной прокрутки, кнопки не перекрыты.

## Дизайн-система

### Зачем она

Раньше стили жили на страницах: одна и та же кнопка описывалась заново, инлайн-стили
перебивали адаптив, а исправление в одном месте не доезжало до остальных. Теперь
внешний вид задаётся токенами и компонентами, страницы только собирают их.

Правило простое: **новых стилей на страницах не появляется**. Если для задачи не хватает
компонента — добавьте вариант в `ui/`, а не инлайн-стиль на странице.

### Токены

Единственный источник значений — `src/styles/tokens.css`. Всё остальное обращается
к переменным.

| Группа | Переменные | Значения |
| --- | --- | --- |
| Фон и поверхности | `--bg`, `--bg-deep`, `--surface`, `--surface-soft`, `--surface-sunken` | тёплый светлый фон |
| Текст | `--ink`, `--ink-soft`, `--muted`, `--muted-2`, `--on-brand` | графит |
| Границы | `--line`, `--line-strong` | тонкие |
| Бренд | `--brand`, `--brand-deep`, `--brand-soft`, `--brand-tint`, `--teal` | глубокий зелёный |
| Семантика | `--success`, `--info`, `--warning`, `--error` + `-bg` и `-line` | по четыре значения на состояние |
| Мягкие оттенки | `--tint-sage`, `--tint-sky`, `--tint-sand`, `--tint-clay`, `--tint-mint`, `--tint-lilac` | подложки карточек |
| Типографика | `--text-xs…--text-3xl`, `--leading-*`, `--weight-*`, `--tracking-*` | 12–36 px |
| Интервалы | `--space-1…--space-8` | 4, 8, 12, 16, 24, 32, 48, 64 px |
| Иконки | `--icon-16/20/24/32`, `--icon-stroke` | штрих 1.75 |
| Контролы | `--control-sm/md/lg` | 36, 44, 48 px |
| Скругления | `--radius-xs/sm/base/lg/pill` | 8, 12, 16, 24, 999 px |
| Тени | `--shadow-xs…--shadow-lg`, `--shadow-hover` | деликатные |
| Контейнеры | `--container`, `--container-narrow`, `--container-wide` | 760, 1180, 1320 px |
| Слои | `--z-base`, `--z-sticky`, `--z-header`, `--z-dropdown`, `--z-overlay`, `--z-toast`, `--z-skip` | 1–100 |
| Анимации | `--ease-out-soft`, `--ease-inout`, `--ease-out`, `--dur-*`, `--stagger`, `--reveal-shift` | 90–340 мс |

### Как менять оформление

| Задача | Что править |
| --- | --- |
| Другой акцентный цвет | `--brand`, `--brand-deep`, `--brand-soft`, `--brand-tint`, `--teal` в `tokens.css` |
| Другая плотность интерфейса | `--space-*`, `--control-*`, `--text-*` |
| Более «мягкие» или «строгие» карточки | `--radius-*` и `--shadow-*` |
| Другая скорость и характер анимаций | `--dur-*`, `--ease-out-soft`, `--stagger`, `--reveal-shift` |
| Ширина контента | `--container*` |
| Оттенки состояний | `--success/info/warning/error` вместе с `-bg` и `-line` |

Менять значения нужно только в `tokens.css` — компоненты подхватят их сами. Инлайн-стили
на страницах для этого не нужны и не приветствуются.

### Компоненты

`src/components/ui/` — 22 компонента. Все типизированы, все принимают `class` для
локальных отступов, но не для переопределения внешнего вида.

| Компонент | Варианты и важные свойства |
| --- | --- |
| `Button` | `variant`: primary / secondary / ghost / subtle / danger; `size`: sm / md / lg; `block`, `external`, `icon`, `iconRight`, `disabled` |
| `IconButton` | `icon`, обязательный `label` (доступное имя), `size`, `plain` |
| `Link` | `variant`: default / arrow / muted; `external`, `icon` |
| `Input` | `label`, `hint`, `invalid`, типы text/search/email/tel/url |
| `SearchInput` | готовый combobox с подсказками, `items`, `action`, `submitLabel` |
| `Checkbox` | `label`, `count`, `filter`; с `company` рисует логотип рядом |
| `Badge` | `tone`: neutral / brand / success / info / warning / danger; `size`, `icon` |
| `AudienceSwitch` | `audience`, `block` — сегментированный переключатель с мягким бегунком |
| `Card` | `padding`: none / sm / md / lg; `hover`; полиморфный `as` |
| `CompanyLogo` | `variant`: compact / default / large / wide / lockup; `showName`, `eager` |
| `OfferCard` | карточка предложения: логотип, статус, цена, способ оформления, CTA |
| `CategoryCard` | `category`, `count`, `statuses` — корректно описывает смешанные категории |
| `CompanyCard` | карточка страховщика в списке |
| `SearchSuggestions` | панель подсказок (используется внутри `SearchInput`) |
| `FilterPanel` | группа фильтров каталога |
| `Accordion` | `items`, `idPrefix`, `openFirst`; клавиатура и `inert` для закрытых панелей |
| `ToastViewport` | два live-region и шаблоны иконок для `toast.ts` |
| `EmptyState` | `title`, `description`, `icon`, `actionLabel`, `hidden` |
| `Breadcrumbs` | хлебные крошки с корректной разметкой |
| `MobileMenu` | навигация, разделы каталога, `inert` в закрытом состоянии |
| `Steps` | `steps`, `columns` (2 или 3) — раскладка управляется атрибутом `data-cols` |
| `VersionIndicator` | компактная версия в подвале, индикатор доступного обновления |
| `Reveal` | обёртка для появления блока при прокрутке, `delay` |

Демонстрация всего этого — страница **`/ui-kit/`**: палитра, типографика, интервалы,
радиусы, тени, кнопки во всех вариантах и размерах, состояния полей, все иконки, все
логотипы, карточки, пустые состояния, уведомления, анимации, мобильные компоненты.
Страница помечена `noindex`, закрыта в `robots.txt` и не входит в `sitemap.xml`.
Используются настоящие компоненты, а не копии разметки, поэтому демо не расходится
с продуктом.

### Иконки

Иконки — Lucide через официальную интеграцию `@lucide/astro`. В разметке используется
обёртка `src/components/Icon.astro`, а имена собраны в `src/lib/icons.ts`.

```astro
---
import Icon from '../components/Icon.astro';
---

<Icon name="kasko" size={24} />
<Icon name="info" size={16} title="Подсказка" />
```

```ts
// src/lib/icons.ts
export const icons = {
  kasko: ShieldCheck,
  ogpo: CarFront,
  // ...
} as const;
export type IconName = keyof typeof icons;
```

Правила:

- В клиент не попадает ни одна иконка целиком: SVG вставляется на сборке, JS не нужен.
- Добавляете новую — импортируйте конкретную иконку в `icons.ts` и добавьте ключ.
  Тип `IconName` подскажет опечатку на `npm run check`.
- Размеры — `16 / 20 / 24 / 32` (`--icon-*`), штрих `1.75`, цвет наследуется
  через `currentColor`.
- Декоративные иконки скрыты от скринридеров (`aria-hidden`), содержательные получают
  `title` и `role="img"`. У кнопки-иконки всегда есть `label`.
- Эмодзи вместо иконок в интерфейсе не используются, наборы иконок не смешиваются.

### Логотипы страховщиков

Логотипы лежат локально в `src/assets/logos/`, поэтому не зависят от доступности чужих
сайтов и не создают внешних запросов. Astro импортирует их как модули и сам добавляет
хеш в имя файла.

```ts
// src/data/companies.ts
import nomadMark from '../assets/logos/nomad-mark.png';

logo: {
  mark: nomadMark,
  markWidth: 101,
  markHeight: 100,
  sourceUrl: 'https://nomad.kz/...',
  fetchedAt: '2026-10-23',
}
```

Компонент `CompanyLogo` применяется везде, где показывается компания: карточка
предложения, фильтр, страница компании, страница предложения, список страховщиков.

| Вариант | Где используется |
| --- | --- |
| `compact` | фильтры, строки, узкие места |
| `default` | карточки предложений |
| `large` | шапка страницы компании |
| `wide` | горизонтальный логотип-надпись вместо знака |
| `lockup` | знак + название одним файлом |

Правила:

- Пропорции сохраняются: `object-fit: contain` и внутренние отступы, без обрезки
  горизонтальных логотипов до квадрата.
- Рядом с компактным логотипом всегда остаётся читаемое название компании.
- Логотип не дублирует объявление рядом с ним.
- Файл — настоящий логотип страховщика. Halyk Life и Halyk Bank — разные бренды,
  подменять один другим нельзя.
- Источник и дата получения записаны в [`docs/logos.md`](./docs/logos.md). Там же
  указано, какие официальные файлы получить не удалось и почему.

### Анимации

Характер — спокойный: короткие небольшие перемещения, никаких бесконечных парений,
параллакса, вращающихся логотипов и печатной машинки.

| Что | Как |
| --- | --- |
| Первый экран | opacity 0→1, подъём 12 px, 320–380 мс, шаг 40–50 мс |
| Секции при первом появлении | opacity 0→1, `translateY(12px)`→0, ~340 мс, один раз |
| Карточки в группе | короткими партиями, суммарная задержка ≤ 200 мс |
| Наведение на карточку | подъём 2 px и чуть заметная тень, 160–200 мс, только `(hover: hover) and (pointer: fine)` |
| Кнопки | 140–180 мс, нажатие — краткий масштаб 0.985, фокус — кольцо сразу |
| Переключатель аудитории | мягкое движение подложки 180–220 мс |
| Подсказки поиска | появление с прозрачностью и сдвигом 4 px, 120–160 мс |
| Аккордеон | 180–220 мс, шеврон поворачивается на 180° |
| Мобильное меню | прозрачность и небольшой сдвиг, 180–220 мс |

Основная кривая — `cubic-bezier(0.22, 1, 0.36, 1)` (`--ease-out-soft`).

```astro
---
import Reveal from '../components/ui/Reveal.astro';
---

<Reveal as="section" delay={60}>…</Reveal>
```

Появление секций включает один общий `IntersectionObserver` в `src/lib/motion.ts`.
Класс `.js` ставится инлайн-скриптом в `<head>`; если модуль почему-то не загрузился,
через 2,5 секунды класс снимается и весь контент остаётся видимым. При отключённом JS
контент виден всегда — анимация не является условием доступности.

`prefers-reduced-motion: reduce` обнуляет длительности и сдвиги прямо в токенах
(`--dur-*: 1ms`, `--reveal-shift: 0px`), поэтому компоненты не нужно переписывать.
Motion-анимации уведомлений в этом режиме тоже пропускаются.

### Уведомления

Менеджер уведомлений — `src/lib/toast.ts`. Разметка контейнера и иконки — компонент
`ToastViewport` в `Base.astro`.

```ts
import { toast } from '../lib/toast';

toast.success('Ссылка скопирована');
toast.info('Доступна новая версия сайта', {
  id: 'update',
  description: 'Обновите страницу, чтобы увидеть изменения',
  duration: 12000,
  action: { label: 'Обновить', onClick: () => location.reload(), closeOnClick: false },
});
toast.warning('Проверка ссылки недоступна', { description: 'Сайт страховщика не ответил' });
toast.error('Не удалось загрузить данные', { persistent: true });
toast.closeAll();
```

| Параметр | Что делает |
| --- | --- |
| `id` | Уникальный идентификатор: повторный вызов с тем же `id` не создаёт второй тост |
| `title` | Заголовок (по умолчанию — текст сообщения) |
| `description` | Пояснение под заголовком |
| `duration` | Время показа в миллисекундах |
| `action` | `{ label, onClick, closeOnClick }` — кнопка действия |
| `persistent` | Не закрывать автоматически |

Поведение:

- Время по умолчанию: success 4 с, info 5 с, warning 7 с, error 8 с, с действием 11 с.
- Таймер встаёт на паузу при наведении, фокусе внутри и в скрытой вкладке.
- Одновременно не больше трёх; одинаковые события объединяются.
- Уведомления не забирают фокус. Обычные попадают в вежливый live-region, ошибки —
  в отдельный настойчивый.
- Вид: светлая компактная карточка, SVG-иконка типа, короткий заголовок, пояснение,
  кнопка закрытия, необязательное действие и тонкая полоска оставшегося времени.
  Состояния различаются и цветом, и иконкой.
- Позиция: на компьютере — справа снизу; на телефоне — компактная стопка с отступами
  от краёв и учётом `safe-area`. Если внизу закреплена кнопка оформления, уведомления
  поднимаются над ней.
- Показываются только реальные события. Никаких «Заявка отправлена», которых не было,
  и никаких уведомлений, задерживающих переход на внешний сайт.

Демонстрация всех типов — на `/ui-kit/`, там же кнопки «Стопка» и «Закрыть все».

### Шаги оформления

`Steps` рисует `<ol>` и задаёт число колонок атрибутом `data-cols`. Инлайн-стилей
с фиксированной сеткой на страницах больше нет — именно они ломали вид на телефоне.

```astro
<Steps steps={steps} columns={3} class="steps--spaced" />
```

На ширине ≤ 820 px остаётся две колонки, ≤ 640 px — одна, шаги идут вертикально
и текст занимает нормальную ширину.

## Структура данных

Все данные лежат в `src/data/`. Страницы ничего не дублируют: категории, фильтры,
счётчики, поисковый индекс, `sitemap.xml` и перелинковка строятся из этих файлов
автоматически. Добавление компании или продукта — правка одного файла, без изменения
шаблонов.

Ключевые типы из `src/data/types.ts`:

```ts
export type Audience = 'individual' | 'business';
export type PurchaseMethod = 'online' | 'request' | 'office' | 'partner';
export type ObligationStatus = 'required' | 'voluntary' | 'conditional';

/** Обязательность конкретного предложения, а не категории. */
interface OfferObligation {
  status: ObligationStatus;
  label: string;       // «Обязательно», «Добровольно», «При условиях»
  text: string;        // объяснение простыми словами
  condition?: string;  // когда статус зависит от деятельности клиента
}

interface CompanyLogo {
  mark: ImageMetadata;      // локальный файл знака
  markWidth: number;
  markHeight: number;
  lockup?: ImageMetadata;   // горизонтальный вариант, если есть
  lockupWidth?: number;
  lockupHeight?: number;
  sourceUrl: string;        // откуда взят файл
  fetchedAt: string;        // дата получения
  note?: string;            // ограничения
}

interface Company {
  id: string;
  slug: string;             // адрес: /kompanii/{slug}/
  name: string;
  legalName: string;
  site: string;
  siteLabel: string;
  city: string;
  summary: string;
  facts: string[];
  logo: CompanyLogo;
  note?: string;
}

interface Category {
  id: string;
  slug: string;
  audience: Audience;
  title: string;
  navTitle: string;
  group: string;
  groupTitle: string;
  short: string;
  lead: string;
  icon: IconName;           // ключ из src/lib/icons.ts
  tint: string;
  whoFor: string[];
  /** Описание вида страхования в целом. Не задаёт статус предложений. */
  obligation: { status: ObligationStatus; label: string; text: string };

interface Offer {
  id: string;
```

### Как добавить страховщика

1. Положите официальный логотип в `src/assets/logos/` (SVG или PNG/WebP с прозрачностью,
   достаточного размера) и запишите источник с датой в `docs/logos.md`.
2. Откройте `src/data/companies.ts` и добавьте объект:

```ts
import exampleMark from '../assets/logos/example-mark.svg';

{
  id: 'example',
  slug: 'example-insurance',
  name: 'Example Insurance',
  legalName: 'АО «Страховая компания «Example»',
  site: 'https://example.kz',
  siteLabel: 'example.kz',
  city: 'Алматы',
  summary: 'Короткое описание направления работы компании.',
  facts: ['Что подтверждено на официальном сайте'],

    mark: exampleMark,
    markWidth: 120,
    markHeight: 120,

```

3. Проверьте официальное наименование и адрес сайта на самом сайте компании.
   Не добавляйте рейтинги, награды и количество клиентов — этих данных в проекте нет.

Страница компании, карточка в списке страховщиков и счётчики появятся после сборки
автоматически. Компания без предложений не выводится в каталоге, пока у неё нет
хотя бы одного опубликованного продукта.

### Как добавить предложение

1. Откройте `src/data/products.individual.ts` (физлица) или
   `src/data/products.business.ts` (бизнес).
2. Добавьте объект в массив по образцу соседних. Обязательные правила:
   - `slug` уникален в пределах всего проекта — он становится адресом страницы;
   - `companyId` и `categoryId` должны существовать в `companies.ts` и `categories.ts`;
   - `obligation` заполняется по существу продукта, а не по категории. Добровольный
     ДМС или корпоративное КАСКО получают `voluntary`, даже если категория в целом
     описывает обязательный вид;
   - `purchase.url` — прямая ссылка на страницу оформления или расчёта у страховщика,
     а не главная страница сайта. Если оформление только через менеджера, поставьте
     `method: 'request'` и опишите это в `note`;
   - `source.url` — страница, на которой вы проверяли условия продукта;
   - `checkedAt` — дата проверки в формате `YYYY-MM-DD`;
   - `price` — только подтверждённые цифры. Если стоимость индивидуальна, используйте
     `{ kind: 'individual', text: 'Стоимость рассчитывается индивидуально' }`.
3. Поставьте `status: 'published'`, чтобы продукт появился в каталоге. Значения
   `draft` и `archived` скрывают его со страниц, из поиска и из `sitemap.xml`.

Текст основной кнопки должен совпадать с реальным действием: `Оформить у страховщика`
для онлайн-покупки, `Рассчитать у страховщика` для калькулятора, `Оставить заявку
у страховщика` для формы заявки, `Связаться со страховщиком`, если оформление идёт
через менеджера.

### Как добавить категорию

1. Откройте `src/data/categories.ts` и добавьте объект с нужным `audience`.
2. Заполните `whoFor`, `obligation`, `risks`, `differences` и `faq` — эти блоки
   формируют страницу категории. Помните: `obligation` категории — это описание вида
   страхования в целом, статус продукта он не задаёт.
3. Иконку возьмите из `src/lib/icons.ts`. Если нужной нет, добавьте её туда —
   тип `IconName` не даст опечататься.

Страница категории появится по адресу `/dlya-sebya/{slug}/` или
`/dlya-biznesa/{slug}/`, попадёт в меню, поиск, футер и `sitemap.xml`.

## Обновление и проверка ссылок

Ссылки на сайты страховщиков меняются чаще, чем условия продуктов. Порядок действий:

1. Запустите проверку внешних адресов:

   ```bash
   npm run verify:links
   ```

   Скрипт покажет адреса с ошибкой и файл, где они встречаются. Для каждого
   проблемного адреса откройте сайт страховщика и найдите актуальную страницу продукта.

2. Обновите `source.url` и `purchase.url` в соответствующем файле
   `src/data/products.*.ts`. Если продукт больше не продаётся, поставьте
   `status: 'archived'` — страница исчезнет из каталога, поиска и карты сайта.

3. Обновите дату проверки:

   ```ts
   checkedAt: '2026-10-23',
   ```

   Дата выводится на странице предложения и в блоке источника — по ней видно,
   насколько свежие данные.

4. Проверьте внутренние ссылки после сборки:

   ```bash
   npm run build
   npm run verify:internal
   ```

5. Перед коммитом прогоните типы и регрессии: `npm run check` и
   `node scripts/regression-tests.mjs`.

Дата последнего общего обзора каталога хранится в `src/data/site.ts` в поле
`updatedAt` — она выводится в футере и используется в `sitemap.xml`.

## Версии и релизы

Версия продукта и версия сборки — разные вещи.

### Версия продукта

SemVer в `package.json` (`version`). Правила:

- **MAJOR** — ломающие изменения адресов, структуры данных или поведения интерфейса;
- **MINOR** — новые возможности без ломки существующего;
- **PATCH** — исправления и правки данных.

Версия показывается в подвале как `v1.1.0` и попадает в `/version.json`.

### Версия сборки

`astro.config.mjs` на каждой сборке считает:

```json
{
  "version": "1.1.0",
  "buildId": "4d605cded5bb",
  "commit": "5367bb4",
  "builtAt": "2026-10-23T14:53:40.161Z"
}
```

- `version` — из `package.json`;
- `commit` — `GITHUB_SHA` в CI, иначе короткий SHA из `git rev-parse`;
- `builtAt` — время сборки в UTC;
- `buildId` — первые 12 символов SHA-256 от `version|commit|builtAt`.

Эти же значения встраиваются в страницу как `meta[name="build-id"]` и
`meta[name="app-version"]`. Открытая вкладка сравнивает свой `buildId` с серверным.

### Как выпустить релиз

1. Определите тип изменения по SemVer и поднимите версию:

   ```bash
   npm version minor --no-git-tag-version   # или patch / major
   ```

2. Добавьте раздел в `CHANGELOG.md` по образцу `## 1.1.0 — 2026-10-23` с блоками
   «Исправлено / Добавлено / Изменено / Удалено».
3. Прогоните полный набор проверок:

   ```bash
   npm ci
   npm run check
   npm run build
   node scripts/regression-tests.mjs
   npm run verify:internal
   npm run verify:links:soft
   ```

4. Проверьте сборку в браузере по чек-листу выше, на 390, 768 и 1440 px.
5. Закоммитьте `package.json`, `package-lock.json` и `CHANGELOG.md`, поставьте тег:

   ```bash
   git commit -am "release: 1.1.0"
   git tag v1.1.0
   git push && git push --tags
   ```

6. Опубликуйте сборку целиком (см. «CI и публикация»).

Не смешивайте в одном релизе подъём версии и крупные правки данных: если после
публикации придётся откатываться, будет непонятно, что именно откатывать.

## Кеширование и обновления

### Правила кеширования

Заголовки задаются сервером или хостингом, а не сайтом. Готовый набор лежит
в `public/_headers` — его понимают Netlify, Cloudflare Pages и совместимые хосты:

| Путь | Cache-Control | Почему |
| --- | --- | --- |
| `/_astro/*` | `public, max-age=31536000, immutable` | в имени файла хеш содержимого |
| `/*.html`, `/` | `no-cache` | новая сборка видна сразу |
| `/version.json` | `no-store` | иначе вкладка не увидит обновление |
| `/robots.txt`, `/sitemap.xml` | `public, max-age=3600` | меняются редко |
| `/favicon.svg`, `/og.svg` | `public, max-age=86400` | статичные картинки |

Кеш не отключается для всего подряд: хешированные файлы кешируются надолго, иначе
каждая загрузка тянула бы шрифты и стили заново. `localStorage` при обычном обновлении
не очищается — выбор аудитории и прочие настройки переживают релиз.

**GitHub Pages файл `_headers` игнорирует** — там заголовки задать нельзя. Для GitHub
Pages работают только хешированные имена файлов и `no-cache` на HTML, который отдаёт
сам хостинг; `/version.json` может отдаваться с задержкой. Если нужен полный контроль
над заголовками, публикуйте на Netlify, Cloudflare Pages или своём nginx.

### Как вкладка узнаёт об обновлении

`src/lib/version.ts`:

- после загрузки — одна лёгкая проверка `fetch('/version.json', { cache: 'no-store' })`;
- при возврате на вкладку — не чаще одного раза в минуту;
- каждые 5 минут, только когда вкладка видима.

Если `buildId` на сервере отличается, показывается одно уведомление «Доступна новая
версия сайта» с кнопкой «Обновить». После его закрытия в подвале остаётся компактный
доступный индикатор обновления. Одно и то же сообщение повторно не показывается
(ключ `polis:update-notified`).

При обновлении сохраняются путь, параметры запроса, фильтры, выбранная аудитория
и позиция прокрутки (`polis:restore-scroll`). Циклов перезагрузки нет: сравнение идёт
по `buildId`, а не по факту загрузки. При сетевой ошибке сайт продолжает работать
молча — проверка не является обязательной для отображения. Service worker для
обновлений не добавлялся: он не нужен и создаёт лишний слой кеша.

### Целостность публикации

Новая версия должна публиковаться целиком. Если хостинг умеет атомарные деплои
(Netlify, Cloudflare Pages, Vercel), используйте их: тогда нет состояния, когда HTML
новый, а хешированные файлы ещё старые. При публикации «по файлам» сначала
выкладывайте `/_astro/`, затем HTML, и только потом `/version.json` — так вкладка
не увидит обновление раньше, чем появятся новые файлы.

## CI и публикация

Workflow — `.github/workflows/ci.yml`. Запускается на pull request и на push в `main`
(плюс вручную через `workflow_dispatch`).

Что делает job «Сборка и проверки»:

1. `actions/checkout` с полной историей — нужен SHA для `buildId`;
2. `actions/setup-node` с Node 22 и кешем npm;
3. `npm ci`;
4. `npm run check` — типы и разметка;
5. `npm run build`;
6. `node scripts/regression-tests.mjs` — 27 регрессионных проверок;
7. `npm run verify:internal` — внутренние ссылки;
8. `npm run version:info` — печать сведений о сборке в лог;
9. `actions/upload-artifact` — `dist/` сохраняется артефактом на 14 дней.

Отдельный job «Внешние ссылки» проверяет сайты страховщиков с `--soft` и **не блокирует**
пайплайн: временная недоступность чужого сайта из сети GitHub — не ошибка проекта.
Скрипт при этом честно разделяет «подтверждённо битую ссылку» (404/410) и «проверка
недоступна» (таймаут, DNS, 403/429).

### Важно про автопубликацию

**GitHub Actions сам по себе сайт не публикует.** Workflow собирает `dist/`, проверяет
его и складывает в артефакт — этого достаточно, чтобы видеть результат каждой сборки
и скачивать готовую статику.

Автоматическая публикация включается отдельно и зависит от хостинга:

- **Netlify / Cloudflare Pages / Vercel** — подключите репозиторий в панели хостинга,
  укажите команду `npm run build` и каталог публикации `dist`. Дальше публикация
  происходит на каждый push в `main` без правок в workflow. Здесь же начнёт работать
  `public/_headers`.
- **GitHub Pages** — добавьте отдельный job с `actions/deploy-pages`
  (`actions/configure-pages`, `actions/upload-pages-artifact` с `path: dist`,
  `actions/deploy-pages`) и разрешите Pages в настройках репозитория
  (`Settings → Pages → Source: GitHub Actions`). Учтите: на GitHub Pages заголовки
  из `_headers` не применяются, а для адреса вида `https://user.github.io/repo/`
  понадобится `base` в `astro.config.mjs` и `PUBLIC_SITE_URL` с этим префиксом.
- **Свой сервер** — забирайте артефакт `dist-<sha>` из запуска workflow и
  распаковывайте на хост; заголовки пропишите в конфигурации nginx.

Платные сервисы для этого не нужны. Секреты в репозиторий не коммитятся: если хостинг
требует токен, он хранится в `Settings → Secrets and variables → Actions`.

## Принципы наполнения

- В каталоге только те продукты, которые удалось подтвердить на официальном сайте
  страховщика. Нет подтверждения — нет карточки.
- Цены указываются только при наличии опубликованных цифр. Во всех остальных случаях
  написано «Стоимость рассчитывается индивидуально».
- Обязательность описывается для каждого предложения отдельно, с пояснением и условием.
  Если статус зависит от деятельности клиента, это написано в карточке, а не выведено
  из категории.
- Нет рейтингов, отзывов, наград, счётчиков клиентов и обещаний вида «самая надёжная
  компания». Порядок компаний в списке — по количеству предложений в каталоге, и это
  прямо указано на странице.
- Итоговые условия всегда определяет договор страховщика. Это написано на страницах
  предложений и в футере.
- Сервис не собирает ИИН, данные документов и номера автомобилей: подбор идёт
  по задаче и характеристикам продукта, а оформление происходит на стороне страховщика.

## Развёртывание

Проект собирается в статику, поэтому подходит любой статический хостинг
(Netlify, Vercel, Cloudflare Pages, GitHub Pages, nginx). Достаточно выполнить
`npm run build` и опубликовать содержимое `dist/`.

Перед публикацией задайте `PUBLIC_SITE_URL` — от него зависят canonical-адреса,
`og:url`, `sitemap.xml` и `robots.txt`. Скопируйте `public/_headers` в настройки
хостинга, если он не читает файл напрямую.

## Ограничения

- Оплата, проверка данных и заключение договора происходят на сайте страховщика —
  на своём сайте их нет.
- Часть процессов оформления требует авторизации в личном кабинете страховщика
  (например, ОГПО ВТС у Nomad) — это отмечено в карточках.
- Не по всем направлениям есть подтверждённые продукты: если предложений нет,
  страница категории показывает честное пустое состояние вместо выдуманных данных.
- Личного кабинета, избранного и онлайн-калькулятора нет.
- По части страховщиков официальный файл логотипа получить не удалось в удобном виде;
  конкретные ограничения (размер, отсутствие квадратного знака, только wordmark)
  перечислены в [`docs/logos.md`](./docs/logos.md).
- Автоматическая публикация требует подключения хостинга — GitHub Actions только
  собирает и проверяет.
