# Учёт редакционных проверок

- `checkedAt` — дата, когда сведения предложения сверяли с указанной официальной страницей в `source`. Это не дата изменения текста.
- `editorial.sourceCheckedAt` повторяет `checkedAt` для явного отображения в редакционном процессе; валидатор не позволяет этим датам расходиться.
- `editorial.nextReviewAt` вычисляется как `checkedAt` плюс 90 дней. Это рабочий срок повторной проверки быстро меняющихся условий, а не утверждение страховщика.
- `editorial.reviewStatus` автоматически равен `scheduled` до наступления срока и `due` начиная с этой даты.
- `editorial.visibility` вычисляется из состояния предложения: `published` → `public`; `draft` и `archived` → `internal`.
- `editorial.contentModifiedAt` указывается только при наличии достоверной истории изменения редакционного содержания. Для прежних правок дата неизвестна, поэтому поле не заполняется.
- `editorial.notes.public` предназначено для заметки, которую можно показать посетителю; `editorial.notes.internal` — для команды. Оба поля необязательны; внутренние заметки нельзя выводить на публичные страницы.

## Проверка предложений и сообщений

Посетители могут открыть подготовленный черновик публичного сообщения в [GitHub Issues](https://strahovka.esl.kz/o-servise/#contacts). В черновике есть поля для продукта или раздела, официального источника и сути замечания, а также предупреждение о публичности. Для отправки потребуется аккаунт GitHub. Если речь об изменении условий или добавлении продукта, нужен официальный первоисточник страховщика. Сообщение пользователя — повод для проверки, но не подтверждение факта.

Редактор проверяет текущую официальную страницу продукта, правила или документы страховщика и фиксирует дату фактической проверки. Для каждого изменяемого утверждения сверяются применимость к нужному продукту/аудитории, покрытие, лимиты, исключения, способ оформления и цена — только в той части, которую подтверждает первоисточник. Если официальный источник не позволяет подтвердить сведения, их не добавляют или явно оставляют неизвестными; ограничение и причину фиксируют во внутреннем комментарии/аудите источника.

После подтверждения редактор меняет источник данных в `src/data/products.*.ts` и связанные структурированные поля, обновляет `checkedAt` только для действительно проверенного источника и при необходимости дополняет аудит в `docs/`. Затем выполняются `npm run check`, `npm run test:data`, `npm run build`, `npm run verify:internal`, `node scripts/regression-tests.mjs` и `npm run test:browser`. Изменение сверяется с первоисточником; перед публикацией создаётся резервная копия, после публикации проверяются страница и `version.json`, а журнал этапов обновляется в `docs/plan-status.md`.

GitHub Issues публичны. Через форму нельзя запрашивать или публиковать ИИН, паспортные данные, телефоны, государственные номера, полисы, платёжные сведения и копии документов. Каталог не собирает эти сведения для проверки предложений и не рассматривает пользовательское сообщение как индивидуальную консультацию.

Даты проверки в каталоге должны отражать реальную проверку источника; прошедшее значение нельзя автоматически переносить на текущую дату. Следующий срок повторного просмотра вычисляется по принятой 90-дневной редакционной политике.
